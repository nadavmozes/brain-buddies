# Batch 1 P0: streak de-dup, color-blind answer cue, local analytics, Money Math change

This batch fixes two correctness/content gaps and adds two UX/privacy improvements to the live BrainBuddies kids' app. Number Quest's private daily-streak implementation is deleted so the hub-wide `PlayerProfile` streak is the single source of truth, and both NQ screens repoint to it. A shared `AnswerBadge` adds a check/cross icon over answered tiles across the five multiple-choice games, giving red/green color-blind kids a non-color correctness cue on top of the existing fills and SFX. A local-only, COPPA-safe `AnalyticsService` records aggregate counters behind an `AnalyticsSink` interface wired through `PlayerProfile`. Money Math gains a Vault-only `makeChange` question type so the Vault's advertised "making change" content actually appears.

Watch for: nothing blocking. The analytics sink intentionally fires round/open counters synchronously with fire-and-forget disk writes (confirmed), which is correct for aggregate counters but means a hard crash mid-write could drop the very last increment — acceptable for this data class.

**Verdict**: APPROVED

## High-level view

The streak de-dup is a clean deletion: the second implementation in `game_state.dart` is gone (fields, pref keys, getter, updater, load/reset wiring, and the day-key helpers), and a worktree-tracked grep confirms no `state.dailyStreak` or stray `daily_streak`/`last_day` keys survive under `lib/games/number_quest/`. The shared streak keeps advancing because `completeLevel` already routes through `profile.onRoundFinished`.

The answer-cue change is additive and uniform. One `const AnswerBadge({show, correct})` widget is layered with `Stack(clipBehavior: Clip.none)` + `Positioned(top:-6, right:-6)` over every answered correct/chosen-wrong tile, in both tile shapes the app uses (text `ComicButton` and visual `Container`). The existing `_bg`/`_bgFor` fills, `textColor` flips, and SFX are left exactly as they were, so the only behavioral delta is the extra icon. Memory Match, which has no choice grid, is correctly untouched.

The analytics seam keeps `PlayerProfile` decoupled: it holds an `AnalyticsSink?` and never names the concrete service. Opens are counted before the already-played early return so repeat opens register; round-end counters and the latest streak/pet/coins snapshots are written at the end of `onRoundFinished`. Everything is `analytics_`-prefixed counters in `SharedPreferences` with no network, PII, or timestamps, and the hub attaches exactly one instance before any gameplay.

Money Math's new `makeChange` reuses the text-choice shape (prompt + `textChoices` + `correctIndex`), is gated to the Vault world via a `MoneyWorld` parameter that defaults to a non-Vault world so existing callers and tests are unaffected, and renders through the existing `_TextChoices` path.

A `git grep` against the worktree returns zero hits for `state.dailyStreak`, `daily_streak`, `last_day`, `_dayKey`, `_todayKey`, `_updateDailyStreak`, and `_dailyStreak` under `lib/games/number_quest/`. ### AnswerBadge as a non-color correctness channel

```
tile (ComicButton | Container)
└─ Stack(clipBehavior: Clip.none)
   ├─ existing tile  (unchanged fill via _bg/_bgFor + textColor flip + onAnswer/SFX)
   └─ Positioned(top:-6, right:-6)
      └─ AnswerBadge(show: answered && (correct || selected), correct: index==correctIndex)
```

`AnswerBadge({show, correct})` returns `SizedBox.shrink()` until the tile is answered, then a 26px circular chip — `Icons.check_rounded` on `AppTheme.success` for the correct tile, `Icons.close_rounded` on `AppTheme.danger` for the chosen-wrong tile — with a 2.5px ink border and `comicShadow`. It is applied consistently to both tile shapes the codebase uses: text `ComicButton` tiles (Number Quest `_ChoiceGrid`, Word Wizard `_ChoiceGrid`, Shape Safari text choices, Clock Hero `_TextChoices`, Money Math `_TextChoices`) and visual `Container` tiles (Shape Safari shapes, Clock Hero clock faces, Money Math `_TwoPiles` and `_PileChoices`). The `show` predicate matches the pre-existing highlight predicate in each screen (`answered && (index==correctIndex || index==selectedIndex)`, or the local `highlighted`/`isCorrect`/`isSelected` variables), so the icon appears on exactly the tiles that already change color. Crucially the diffs wrap the original tile untouched — the `color:`, `textColor:`, and `onPressed:` expressions are byte-for-byte the same inside the new `Stack` — so color and SFX behavior is preserved and the change is purely a visible-icon addition. Memory Match has no choice grid and shows no diff (confirmed via `git diff --name-only`).

### Local-only analytics behind an interface

`AnalyticsSink` declares `recordGameOpened`, `recordRound`, and `updateSnapshots`; `AnalyticsService extends ChangeNotifier implements AnalyticsSink` backs them with `SharedPreferences`. Every key is `analytics_`-prefixed (`opens_<gameId>`, `rounds_total`, `correct_total`, `threestar_total`, `boss_total`, `snap_streak`, `snap_pet`, `snap_coins`), reads are defensive (`getInt(...) ?? 0`), and there is no network call, no PII, and no timestamp of any granularity — only running totals and overwrite-style snapshots. `PlayerProfile` holds `AnalyticsSink? _analytics` and `attachAnalytics(sink)` and never references the concrete class. `recordGameOpened` is the first statement of `recordGamePlayed`, ahead of the `_playedGames.contains` early return, so repeat opens still increment. `recordRound` and `updateSnapshots(streak: dailyStreak, petLevel: petLevel, coins: coins)` run after the existing round work in `onRoundFinished`. The hub creates one `AnalyticsService`, and inside the existing `_profile.load().then(...)` chain it `await`s `_analytics.load()` then `_profile.attachAnalytics(_analytics)` before `_profileReady` flips, so the sink is attached before any game can be opened or any round can finish.

The sync counter methods (`recordGameOpened`, `recordRound`) update the in-memory `SharedPreferences` cache immediately and let the `setInt` future resolve in the background. The failure edge is that a crash between the in-memory bump and the disk flush drops the last counter tick — tolerable for aggregate analytics but worth noting as a fire-and-forget write.

### Money Math make-change, Vault-gated

`MoneyQuestionType.makeChange` reuses the existing `prompt` + `textChoices` + `correctIndex` fields, so no model surface grows. The generator threads a `MoneyWorld world` parameter through `generateRound` and `generateOne` with a `MoneyWorld.piggy` default, which keeps every pre-existing caller and test behaving identically; `forLevel` passes `level.world`. `makeChange` is added to the candidate type list only when `world == MoneyWorld.vault`, so it is impossible to surface outside the Vault — the `non-Vault worlds never produce makeChange` test sweeps all other worlds across 50 seeds to confirm. `_makeChange` picks a price and a payment as 5-cent multiples with payment at least 5 cents above price, so `correct = pay - price` is always positive; `_distinctAmounts` yields four distinct non-negative options including the answer, and the `_signature` (`type|prompt|...`) keeps the dedupe loop effective. `money_game_screen._buildBody` routes `makeChange` to the existing `_TextChoices` widget — no coin-pile panel. The positive-seed test parses the correct label (`"<n>¢"`) back to an int and asserts it is non-negative and present among the choices.
